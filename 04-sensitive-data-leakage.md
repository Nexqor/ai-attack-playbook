# 04 · Sensitive Data Leakage

**Target:** system prompts, training data, RAG stores · **Severity:** 🔴 High · **OWASP:** LLM02, LLM07

## TL;DR
AI systems leak what they were given: secrets in system prompts, memorized training data, and documents a user should never see but the RAG pipeline retrieved anyway.

## How it works
- **System prompt leakage:** the model is asked (or injected) to repeat its instructions.
- **Training data extraction:** repeated or crafted prompts make the model reproduce memorized text ([Carlini et al., 2021](https://arxiv.org/abs/2012.07805)).
- **RAG over-sharing:** the retriever ignores document permissions, so any user can ask about HR files or contracts.
- **Exfiltration via rendering:** the model outputs a Markdown image whose URL carries stolen data; the client loads it automatically.

## Real-world example
The **Fireworks AI** breach (2026) exposed API keys, partial model weights, customer datasets and Notion AI chat transcripts ([The Hacker News](https://thehackernews.com/2026/11/fireworks-ai-breach-widens-to-expose.html)). AI platforms concentrate exactly the data attackers want.

## Detection
- DLP on model outputs: keys, tokens, PII, internal hostnames.
- Monitor outbound image/link URLs generated by the model.
- Audit which documents each RAG query retrieved, per user.

## Defense (by impact)
1. **Permission-aware retrieval:** filter documents by the requesting user's ACL *before* the model sees them.
2. **No secrets in prompts.** Use server-side tool calls with scoped credentials.
3. **Block auto-loading of external images/links** in AI chat clients, or proxy them.
4. **Data minimization:** don't fine-tune on data you can't afford to leak.
5. **Short retention** for chat logs and prompt history.
